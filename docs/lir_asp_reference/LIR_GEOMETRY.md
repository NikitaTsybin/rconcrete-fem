# Прямое чтение геометрии LIR

## Статус

Указанные смещения экспериментально проверены для контрольного LIR из README.
Все узлы и связи сверены с ранее полученной COM-выгрузкой той же модели.
Чтение возможно без запущенной ЛИРА; исходный файл открывать только на чтение.

**Не закончено:** разбор словаря определений типов КЭ в самом файле. Для
контрольной модели соответствие внутренних индексов типам подтверждено API.
Не распространять эту таблицу автоматически на другой LIR.

## Формат чисел и заголовок

Все описанные числа little-endian. Смещения в байтах, с нуля.
Не использовать `transmute`, `repr(C)` и чтение структуры с платформенным padding.

| Смещение | Размер | Содержание |
|---:|---:|---|
| 0 | 37 | ASCII `$LIRA-SAPR 2013 software ver.13.0.0.a` |
| 37..48 | 12 | Неинтерпретированные поля; не использовать как версию/счётчики |
| 49 | 4 | `u32`: число записей узлов, в примере 114309 |
| 53 | 4 | Неинтерпретированное поле |
| 57 | 4 | `u32`: число записей элементов, в примере 161823 |
| 61..88 | 28 | Поля заголовка, семантика не установлена |
| 89 | — | Начало массива узлов |

Наличие строки «2013» НЕ означает, что открыта ЛИРА 2013: контрольный файл
прочитан из модели ЛИРА 2021. Один префикс не гарантирует одинаковую структуру
всех файлов. Проверять сигнатуру, границы, счётчики и независимые примеры.

## Узлы: 28 байт на запись

```text
node_offset(i) = 89 + i * 28          // i с 0
```

| Внутри записи | Тип | Значение |
|---:|---|---|
| +0 | f64 | X |
| +8 | f64 | Y |
| +16 | f64 | Z |
| +24 | u32 | Исходное поле-флаг; у всех узлов примера равно 1 |

В примере номер узла API = `i+1`. Для файлов с удалёнными записями и другой
нумерацией это не проверено. Не удалять записи и не перенумеровывать по флагу,
пока семантика флага и возможных таблиц перенумерации не установлена.

Координаты хранятся как f64, но значения контрольной модели имеют точность
исходных float32. Не округлять их при хранении. Текстовые шапки/формат файла
не доказывают единицы: для этой модели метры подтверждены API и ASP, в другом
проекте единицы надо установить отдельно.

Первые два узла:

```text
1: (-1.1050000190734863, 4.978000164031982, -8.90000057220459)
2: (-1.1230000257492065, 5.229000091552734, -8.90000057220459)
```

## Элементы: 38 байт на запись

```text
elements_start = 89 + node_count * 28
element_offset(i) = elements_start + i * 38
elements_end = elements_start + element_count * 38
```

В контрольном файле `elements_start=3200741`, `elements_end=9350015`.

| Внутри записи | Тип | Значение |
|---:|---|---|
| +0..31 | 8 × u32 | Слоты внутренних индексов узлов |
| +32 | u16 | Внутренний индекс определения типа элемента |
| +34 | u32 | Исходное поле-флаг; у всех элементов примера равно 1 |

В примере номер элемента API = `i+1`. Связи используют внутренние индексы узлов
с нуля: для действительного слота `node_id = raw_node_index+1`.

**Не путать индекс определения типа с номером КЭ.** Поле `+32` не содержит 10/42/44/56.

Только для контрольной модели подтверждена таблица:

| Внутренний индекс +32 | Тип КЭ API | Число действительных слотов | Число элементов |
|---:|---:|---:|---:|
| 0 | 10 | 2 | 202 |
| 1 | 42 | 3 | 25794 |
| 2 | 44 | 4 | 99516 |
| 3 | 56 | 1 | 36311 |

Для другого файла индекс 0 может обозначать другой тип. Пока словарь не разобран,
принимать в парсер отдельный **проверенный для данного файла** `type_map`, либо
возвращать сырой `definition_index`, не заявляя полноценную топологию.

### Критическая ловушка неиспользуемых слотов

Нельзя считать все восемь слотов связями. Нельзя прекращать чтение на первом нуле:
сырой индекс 0 — действительный узел №1. Неиспользуемые слоты могут быть ненулевыми.

Примеры:

```text
Элемент 1, КЭ 10:
raw slots: [36131, 36132, 0, 0, 0, 0, 0, 0]
действительные узлы: [36132, 36133]

Элемент 164, КЭ 44:
raw slots: [0, 30, 1, 20, 0, 0, 0, 0]
действительные узлы: [1, 31, 2, 21]

Элемент 178, КЭ 42:
raw slots: [93, 122, 83, 63, 0, 0, 0, 0]
действительные узлы: [94, 123, 84]; четвёртый слот 63 НЕ использовать

Элемент 125513, КЭ 56:
raw slots: [8958, 111738, 36920, 111737, 0, 0, 0, 0]
действительный узел: [8959]; остальные НЕ использовать
```

Сохранять порядок действительных узлов — он влияет на ориентацию КЭ.
Сортировать связи допустимо только во временном ключе геометрического поиска,
не в итоговой модели.

## Заготовка Rust: только безопасное чтение примитивов

```rust
use anyhow::{Context, Result};

fn at<const N: usize>(b: &[u8], o: usize) -> Result<[u8; N]> {
    let end = o.checked_add(N).context("offset overflow")?;
    Ok(b.get(o..end).context("truncated LIR")?.try_into()?)
}
fn u32_at(b: &[u8], o: usize) -> Result<u32> {
    Ok(u32::from_le_bytes(at::<4>(b, o)?))
}
fn u16_at(b: &[u8], o: usize) -> Result<u16> {
    Ok(u16::from_le_bytes(at::<2>(b, o)?))
}
fn f64_at(b: &[u8], o: usize) -> Result<f64> {
    let v = f64::from_le_bytes(at::<8>(b, o)?);
    anyhow::ensure!(v.is_finite(), "invalid coordinate");
    Ok(v)
}
// Перед циклом: checked_mul/checked_add для размеров и проверка elements_end <= b.len().
// Слоты: std::array::from_fn::<_,8,_>(...) нельзя читать с unwrap из непроверенного файла.
```

Это не готовый универсальный LIR-парсер. Отдельного реализованного Rust-модуля
LIR в комплекте нет: прямое чтение проверялось read-only диагностикой Python.
Rust-приложению Python для реализации этого формата не нужен.

## Минимальные проверки перед использованием

1. Сигнатура, длина минимум 89, checked arithmetic, весь блок помещается в файл.
2. Разумные пределы счётчиков до выделения памяти.
3. Все координаты конечны; сохранить флаги без домыслов.
4. Проверенный для данного файла словарь типов и число действительных узлов.
5. Действительные индексы узлов в диапазоне `0..node_count`.
6. Не считать наличие ненулевых хвостовых слотов признаком многогранного элемента.
7. На новой версии/неизвестном типе останавливаться, а не угадывать.
8. Сверить независимые узлы и элементы каждого семейства с UI/API/официальным
   текстовым экспортом. Для контрольного файла сравнены все 512161 связи.

Остальная часть LIR после `elements_end` не декодирована. Поля жёсткостей, нагрузок,
материалов, расчётные результаты и таблицы перенумерации из этого описания не следуют.
